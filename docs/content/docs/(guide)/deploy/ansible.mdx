Rookery's install methods are wrappers around one Ansible role, `provision/ansible/roles/rookery` in the provisioning source. It can also run on its own.

<Callout type="warn" title="Dedicated machines only">
  Ansible does not partition anything, but the role installs services, changes the firewall policy and grants host-wide sudo. Run it only on a machine set aside for agents, not on your everyday computer.
</Callout>

## From Rookery

`rookery host create HOST --method apply` runs the role with the host's profile, against the machine Rookery runs on or against an inventory. `--set inventory=PATH` names the inventory, and `ask_become_pass` says whether Rookery asks for a sudo password. Rookery warns when it would provision the machine Rookery runs on.

## Without Rookery

Install Ansible into a virtualenv in a source checkout first, and point Ansible at the role's settings, as Rookery does:

```bash
python3 -m venv .venv && .venv/bin/pip install -r provision/requirements.txt
export ANSIBLE_CONFIG=provision/ansible.cfg
```

On the target itself:

```bash
.venv/bin/ansible-playbook -i localhost, -c local provision/ansible/site.yml \
  --become --ask-become-pass -e rookery_profile=cloud
```

</Tab>
<Tab value="Remote inventory">

Put the inventory and its variables in a private file:

```yaml title="secrets/hosts.yml"
all:
  hosts:
    agent-cloud:
      ansible_host: 203.0.113.10
      ansible_user: ops
      rookery_profile: cloud
      rookery_bootstrap_ssh_cidr: 198.51.100.7/32
```

```bash
.venv/bin/ansible-playbook -i secrets/hosts.yml provision/ansible/site.yml --become
```

Remote runs also leave the current SSH source address open in the firewall when it is known.

## Targets

`rookery_profile` selects defaults for the target, the kind of machine the host is installed on. A Rookery profile says it as `target`:

| Target | For |
| --- | --- |
| `laptop` | Physical machines, with the LightDM login and power defaults |
| `cloud` | Cloud instances, virtual machines and tests. Set a bootstrap SSH CIDR to limit SSH, such as `10.0.2.2/32` for a QEMU guest |
| `container` | The container image |

Cloud networking and disks are left as they are on every target. The agent's username and home are configurable, and its UID is discovered rather than assumed.

## Settings

Every `rookery_` setting has its default in [`provision/ansible/roles/rookery/defaults/main.yml`](https://github.com/aiviarium/rookery/blob/main/provision/ansible/roles/rookery/defaults/main.yml). In a Rookery profile they go under `ansible_vars`; with plain Ansible, in the inventory or with `-e`. Plugins are chosen with `rookery_plugin_features`, and plugins outside the source's `plugins/` folder are found through `rookery_plugin_dirs` (`{"ID": "/path"}`).

External programs are installed as the agent. Versions are pinned where upstream allows it. See [Tools](/docs/reference/tools#versions) and [Validation](/docs/reference/validation).
