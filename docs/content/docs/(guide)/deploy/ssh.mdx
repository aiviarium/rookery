title: Existing server over SSH
description: Set up an Ubuntu 26.04 machine you can already log in to, without reinstalling it.

This method runs the role over SSH against a machine that already has Ubuntu. The role adds accounts, packages and services to the existing system without partitioning or reinstalling.

A machine that should stay as it is can be added with only an address instead, and get Rookery's controller alone or nothing at all ([Host types](/docs/use/types)). `type` says which.

<Callout type="warn" title="Dedicated machines only">
  The role installs services, changes the firewall policy and grants the agent sudo for the entire machine. Do not point it at a computer you use for anything else.
</Callout>

## Requirements

- Ubuntu 26.04 on amd64
- Python 3
- SSH access with a login that can use sudo

Your machine needs `ssh` and `ansible-playbook` ([Install](/docs/start/install#what-else-rookery-uses)).

## Install

<Steps>
<Step>

### Choose the method

`rookery host create studio --method ssh` asks for the way to log in and the address first.

</Step>
<Step>

### Give the address

It asks for the address as `address`: a hostname, an IP address or a `Host` alias from your SSH configuration. Rookery logs in from the machine its server runs on, with that machine's SSH configuration and its aliases.

</Step>
<Step>

### Say how to log in

`login` says how Rookery logs in ([Logging in to hosts](/docs/use/accounts#logging-in-to-hosts)). The default is [the key of Rookery itself](/docs/reference/profile#the-key-of-rookery-itself). `ssh` uses your own ssh-agent and SSH configuration. A host that doesn't take Rookery's key yet gets it with `rookery key trust HOST` and a password used once. `ask_become_pass` says whether Rookery asks for a sudo password on the target. Rookery records the host's SSH host key at the first login, and refuses the host if the key changes later.

</Step>
<Step>

### Run

Answer the rest of the questions, and answer yes to applying it. Rookery writes a temporary private Ansible inventory and runs the role against the host in your terminal, through `rookery apply studio`. When it finishes, the profile keeps the SSH address and `rookery host show studio` says how the host is.

</Step>
</Steps>

## The firewall

The role turns on UFW. It keeps SSH open for the address you installed from and for the recovery SSH CIDR, `bootstrap_ssh_cidr`, if you set one. Everything else, including Cockpit, goes through the tailnet: UFW allows management on `tailscale0`.

<Callout type="warn">
  Remove a temporary SSH rule only after checking that SSH over the tailnet works.
</Callout>

Docker's published ports can bypass UFW's input rules. Publish project services on loopback, or set Docker's forwarding policy yourself.

## Applying changes later

The same profile installs the host again with `rookery apply studio`, such as after switching a feature on. Applying is safe to repeat, and a second run on an unchanged profile does not change anything.

Profiles of other kinds, and installing without Rookery, are on [Ansible directly](/docs/deploy/ansible).
