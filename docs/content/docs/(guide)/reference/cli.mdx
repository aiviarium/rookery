This page is generated from the commands themselves. [The command line](/docs/use/cli) explains them by what they do.

## Flags of every command

| Flag | What it does |
| --- | --- |
| `--server URL` | Use this rookery server for this command: https://HOST, http://HOST:PORT or unix:/path. rookery login keeps one. |
| `--token-file FILE` | Read the server's token from this file. |
| `--token-stdin` | Read the server's token from standard input. |
| `-o, --output OUTPUT` | What is printed on standard output: a table for people, or the API's own JSON. One of `table`, `json`. By default `table`. |
| `--no-input` | Never ask. What is missing is an error that names the flag to pass. |
| `-y, --yes` | Answer yes to a confirmation. |
| `-q, --quiet` | Print only the result. |
| `--sudo-password-stdin` | Read the SSH user's sudo password from standard input, for a host whose sudo asks for one. |
| `--color WHEN` | Colours: on a terminal, always or never. NO_COLOR turns them off as well. One of `auto`, `always`, `never`. By default `auto`. |

Flags go before or after the names, as `--tail 50` or `--tail=50`. `--` ends the flags; what follows it is passed on as it is.

## Exit statuses

| Status | Means |
| --- | --- |
| 0 | done |
| 1 | the work failed: a job failed, or a host did not answer |
| 2 | the command line was wrong: an unknown word, a missing value, a bad flag |
| 3 | refused: the role is too low, the host or this server cannot do it now, or a confirmation was declined |
| 4 | the server could not be reached |

A command run on a host, such as `rookery exec`, ends with that command's own status.

## Environment

| Variable | What it does |
| --- | --- |
| `ROOKERY_SERVER` | The server, when no --server is given. It wins over the one rookery login kept. |
| `ROOKERY_TOKEN` | Its token, when no --token-file or --token-stdin is given. For containers and CI. |
| `NO_COLOR` | No colours, as --color never. |
| `ROOKERY_ and a setting's name` | A setting of the server, in capitals, such as ROOKERY_RETENTION_DAYS, for a server in a container. |
| `XDG_CONFIG_HOME, XDG_DATA_HOME, XDG_RUNTIME_DIR` | Where rookery keeps its settings, its data and its socket. |
| `VISUAL, EDITOR` | The editor of rookery host edit. |

### rookery host create

Describe a new host, then install it. Asks what is missing on a terminal.

```text
rookery host create NAME [--method METHOD] [--from PROFILE] [--type TYPE] [--feature FEATURE] [--no-feature FEATURE] [--set KEY=VALUE] [--generate-passwords] [--provisioner PROVISIONER] [NAME=VALUE…] [--run] [--detach]
```

| Argument | What it is |
| --- | --- |
| `NAME` | Its name. |
| `--method METHOD` | How it is installed: provisioner, iso, cloud-seed, ssh or ssh-only. |
| `--from PROFILE` | Start from a profile: a host's name, a JSON file, or - for standard input. |
| `--type TYPE` | What rookery does with it: workstation, or node for a server of machines, applied over SSH. |
| `--feature FEATURE` | Switch on a plugin's feature, PLUGIN/FEATURE. Again for more. |
| `--no-feature FEATURE` | Switch off a plugin's feature. |
| `--set KEY=VALUE` | Set a field of the profile. Again for more; the keys are listed below. |
| `--generate-passwords` | Generate the accounts' passwords; rookery host credentials NAME shows them. |
| `--provisioner PROVISIONER` | Make the machine with this provisioner, which also sets it up. |
| `NAME=VALUE…` | The provisioner's arguments, such as cpus=2. |
| `--run` | Install it once it is saved: apply, render the seed or build the installer. |
| `--detach` | Print the job's id and return; rookery job wait ID waits for it. Needs a rookery serve. |

| `ssh-only` | Existing host, SSH only |
