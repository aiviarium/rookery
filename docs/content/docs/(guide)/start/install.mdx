Rookery sets hosts up from Linux. The program contains everything it puts on a host, so installing it means placing one file on your `PATH`. On macOS and Windows the same program is a client of a [Rookery server](/docs/use/server) on another machine.

<Tabs items={['Install script', 'Windows', 'Cargo', 'Container image']}>
<Tab value="Install script">

```bash title="Linux and macOS"
curl -fsSL https://raw.githubusercontent.com/aiviarium/rookery/main/install.sh | sh
```

The script downloads the latest release for this machine from GitHub, checks it against its SHA-256 and installs it to `~/.local/bin/rookery`. Releases have it for Linux on x86_64 and arm64, and for macOS on Apple silicon and Intel.

| Variable | Effect |
| --- | --- |
| `ROOKERY_INSTALL_DIR` | Install somewhere else than `~/.local/bin` |
| `ROOKERY_VERSION` | Install a release tag such as `v0.2.0` instead of the latest |

On other architectures, build it with cargo.

</Tab>
<Tab value="Windows">

```powershell title="Windows, in PowerShell"
irm https://raw.githubusercontent.com/aiviarium/rookery/main/install.ps1 | iex
```

The script installs `rookery.exe` to `%LOCALAPPDATA%\Programs\rookery`, checked in the same way. `ROOKERY_INSTALL_DIR` and `ROOKERY_VERSION` work as for `install.sh`. See [From macOS or Windows](/docs/use/server#on-other-systems).

</Tab>
<Tab value="Cargo">

Building needs Rust 1.88 or newer, Python 3 and the musl target, because the build also makes the two static programs every host gets, `rookeryd` and `box`:

```bash
rustup target add x86_64-unknown-linux-musl
cargo install --locked --git https://github.com/aiviarium/rookery rookery
```

From a checkout, `cargo install --locked --path crates/rookery` does the same. On macOS and Windows the build is the client alone, which only needs Rust.

</Tab>
<Tab value="Container image">

`ghcr.io/aiviarium/rookery` holds Rookery with SSH, Python and Ansible beside it. Its default command is `rookery serve` on port 7777:

```bash
docker run -d --name rookery -p 127.0.0.1:7777:7777 \
  -v rookery-config:/config -v rookery-data:/data \
  -v ~/.ssh:/home/rookery/.ssh:ro \
  ghcr.io/aiviarium/rookery
```

Any other command goes after the image name, such as `ls`, or `ui` for the screens:

```bash
docker run --rm -it -v rookery-config:/config -v rookery-data:/data ghcr.io/aiviarium/rookery ls
docker run --rm -it -v rookery-config:/config -v rookery-data:/data \
  -v ~/.ssh:/home/rookery/.ssh:ro ghcr.io/aiviarium/rookery ui
```

See [rookery serve](/docs/extend/serve#in-a-container) for the volumes and the token. A Rookery installed on your machine uses the container's hosts once it has logged in with a setup key made there:

```bash
docker exec rookery rookery server setup-key
rookery login http://127.0.0.1:7777
rookery ls
```

See [A Rookery server](/docs/use/server).

</Tab>
</Tabs>

Check it:

```bash
rookery --version
rookery
```

## What else Rookery uses

| For | Needs |
| --- | --- |
| Setting up a host over SSH or applying its configuration | `ssh`, `python3`, `ansible-playbook` (ansible-core 2.21, which needs Python 3.12 or newer) |
| Building a USB installer | `python3`, `xorriso`, `curl` |
| Hashing passwords | `openssl` |
| Installing plugins from a registry | `npm` |

The install script lists what is missing. A source checkout with a `.venv` gets its own `ansible-playbook` from there:

```bash
python3 -m venv .venv && .venv/bin/pip install -r provision/requirements.txt
```

## Where Rookery keeps things

| What | Where |
| --- | --- |
| Settings of this machine, listed below | `~/.config/rookery/config.json` |
| The other settings, registries, secret values and registry passwords | Rookery's store, by default `~/.local/share/rookery/rookery.db` |
| One profile per host, its generated passwords and the record of a machine Rookery created for it | Rookery's store too. `rookery host export HOST` prints a profile and `rookery host credentials HOST` the passwords |
| Rookery's SSH keys, and the token and setup key of `rookery serve` | Rookery's store. A key is written to `~/.local/share/rookery/keys/NAME` when ssh needs it, and the token to `serve.token` |
| The key file of an encrypted store | `~/.config/rookery/store.key` (setting `store_key`) |
| Locks held while Rookery creates or changes a host's machine | `~/.local/share/rookery/locks/` |
| Your own plugins | `~/.config/rookery/plugins/`, and in Rookery's store what reinstalls them |
| Provisioning source, unpacked from the program | `~/.local/share/rookery/source/` |
| Build output such as the release archive, seeds and installer images | `~/.local/share/rookery/build/` |
| Downloaded Ubuntu installer ISOs | `~/.local/share/rookery/iso/` (setting `iso_dir`) |

`XDG_CONFIG_HOME` and `XDG_DATA_HOME` are honoured. `rookery config list` prints the paths and settings, and `rookery config set KEY VALUE` changes one, in the file or in the store. The Settings tab of the home screen does the same. `rookery server store status` says where the store is and whether it is encrypted. See [The store](/docs/use/store), which also says how to restore an installation from it.

These settings stay in `config.json`, as they belong to this machine or are needed to open the store:

| Settings | What they are for |
| --- | --- |
| `store`, `store_key`, `store_ca` | Where the store is and how it is opened |
| `server`, `server_token` | The Rookery server this machine uses, kept by `rookery login` |
| `source`, `iso_dir` | Folders on this machine |

A key Rookery does not know stays in `config.json` as it is, such as the OAuth client settings of Rookery 0.4, which Rookery has no use for any more.

An older Rookery kept secrets in `secrets.json`, and registries and all settings in `config.json`. It kept each host's profile in `~/.config/rookery/hosts/NAME.json`, with `NAME.credentials.json` and `NAME.instance.json` beside it. The first run of this Rookery moves all of them into the store. It keeps the old files in `~/.config/rookery/migrated/`, and removes the copies of a Rookery server's profiles in `~/.local/share/rookery/served/`. Delete the old files once the store has what you need. It also puts Rookery's own SSH key, the token of `rookery serve` and your own plugins into the store, and leaves their files where they are. The setup key, which was in `serve.setup-key`, is in the store alone from then on.

<Callout type="warn">
  Profiles hold Wi-Fi passwords, and the store holds generated passwords and the tailnet's API key. They are in clear text unless the store is encrypted, see [The store](/docs/use/store#encrypt-it). Keep the store and its key file private, and keep files that `rookery host export` writes out of version control.
</Callout>

## The provisioning source

The *provisioning source* is what Rookery puts on a host. It holds the Ansible role with `rookeryd` and `box`, the bootstrap scripts and the built-in plugins. It is built into the program and unpacked into the data directory the first time it is needed, and again after an update. The program can be copied to another machine as it is.

Rookery looks for the source in this order:

1. `ROOKERY_SOURCE`
2. the `source` setting
3. a checkout in the current directory, when Rookery is started inside one
4. the built-in copy

To work on the role, point Rookery at your checkout, and clear the setting to go back:

```bash
rookery config set source ~/src/rookery
rookery config set source ""
```
