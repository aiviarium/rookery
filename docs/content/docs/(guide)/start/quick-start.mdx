---
title: Quick start
description: Create a profile for a host, install it, and open its desktop.
icon: Zap
---

This walks through a first host with the commands. The example uses an Ubuntu 26.04 server you can already reach over SSH, at `192.0.2.10`. The other ways to install differ only in the method and what it asks for.

Every command calls a [`rookery serve`](/docs/use/server), which keeps the profiles, secrets and jobs. On the server's own machine the command finds it on its socket. From another machine, sign in with `rookery login https://rookery.example.ts.net` first.

<Callout title="Try it without a machine">
  The [container](/docs/deploy/container) runs the same desktop on Docker, and [QEMU](/docs/deploy/qemu) runs a whole host in a VM.
</Callout>

<Steps>
<Step>

### Create the host

```bash
rookery host create studio
```

The name is new, so Rookery makes a profile and puts its questions. The answers are saved on the server under the name `studio`. `rookery host export studio` prints the profile as JSON, and `rookery host create --help` lists every answer as a flag, for the last section.

</Step>
<Step>

### Choose how to install

The first question is how. Choose **Existing host over SSH**, then give the address: an IP, a hostname or a `Host` alias from your SSH configuration. The Tailscale setting follows.

The methods are on [Deploying](/docs/deploy). A script gives every answer with a flag:

```bash
rookery host create studio --method ssh --set address=192.0.2.10 --set user=ops
```

</Step>
<Step>

### Choose what to install

Then it asks for the tool categories, browsers, Cockpit and the features of the installed plugins, which is where the coding agents are. Say yes or no to each, or pass `--feature PLUGIN/FEATURE` and `--no-feature PLUGIN/FEATURE` for the ones that matter. [Plugins](/docs/extend/plugins) says how to install one.

</Step>
<Step>

### Check the settings

What has a default is asked next. That covers the *operator*, your account on the host, and the *agent* account the coding agents use. An account's SSH public key is given with `rookery host set studio operator_ssh_public_key=ssh-ed25519…`, and each account can take several. The operator also takes [the key of Rookery itself](/docs/reference/profile#the-key-of-rookery-itself), which `rookery key show rookery` prints.

A password hash is not typed: `--generate-passwords` makes the passwords, stores their hashes in the profile, and Rookery keeps the passwords themselves in the server's database. `rookery host credentials studio` shows them.

</Step>
<Step>

### Install

At the end it lists every problem that stops the install, and the flag for each one. Fix them, and answer yes to applying the profile to the host. The command follows the job and says how it went:

```bash
rookery apply studio
```

</Step>
<Step>

### Use the host

Once the host answers, `rookery host show studio` says how it is and what it can do. `rookery run studio status` checks it, and `rookery action list studio` names the rest:

```bash
rookery run studio status
rookery run studio access                   # the address of the desktop
```

`rookery ssh studio` is a shell as the agent, and `rookery exec studio -- uname -a` runs one command.

</Step>
<Step>

### Sign the agents in

Installing a coding agent or a tool does not sign it in. `rookery run studio github:login` and the actions that other plugins add run the tool's sign-in on the host and print its link, which you open in your own browser. See [Sign-ins](/docs/use/sign-ins).

</Step>
</Steps>
