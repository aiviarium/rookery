title: Sign-ins
description: Sign the coding agents, GitHub and T3 Code in on a host, which installing them does not do.

---

A new host has its tools and agents installed but nobody signed in. Each sign-in runs on the host as the agent, and you complete it in your own browser.

## The actions that sign in

| Action | Signs in |
| --- | --- |
| `github:login` | `gh`, from the `github` plugin |
| `unity:login` | The Unity CLI, from the `unity` plugin |
| `show-users` | The accounts every plugin of the host knows about |

`rookery action list studio` names them in their groups, and `rookery run studio github:login` runs one.

A plugin that installs a coding agent adds its sign-in to the same group.

A sign-in runs in your terminal and prints a link. Open it in your browser to finish:

```bash
rookery run studio github:login
rookery action list studio                 # every sign-in the host has
```

## GitHub without signing in

A fine-grained token given to the host as `GH_TOKEN` signs `gh` and `git` in for github.com without a browser. See [Secrets](/docs/use/secrets#github).

## T3 Code on another device

On a host where a plugin installed T3 Code, it asks every new browser to pair once. **Use T3 from another device** prints a pairing link for the published tailnet address, and the host and code for the T3 app. The code works once, within 10 minutes. T3 has to be [published on the tailnet](/docs/use/access#joining-the-tailnet) first.

```bash
rookery run studio pair
```

Keep T3's pairing enabled and use the tailnet HTTPS address, not a loopback pairing address.

## Checking by hand

On the host, as the agent:

```bash title="On the host"
sudo -iu agent
gh auth status
t3 service status
box exec rookery-smoke
```

Run `sudo -n true` from a command T3 started, too, to check the agent's sudo as T3 sees it.
